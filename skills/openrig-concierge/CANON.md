# openrig-concierge — CANON (anchor SSOT)

The canonical decisions this skill enforces. `--mode=anchor` surfaces them and flags drift. Each decision
names the evidence that would reverse it. Checked against `rig` 0.5.14 (cc75efdd).

| # | Decision | Why | Reverse when |
|---|---|---|---|
| C1 | **Fact ladder.** Resolve any OpenRig fact from the highest available rung: (0) live state (`rig ps`, `rig capture`); (1) the installed CLI (`rig --version`, `rig <cmd> --help`, `rig context get <ref>`, `~/.openrig/reference/*.md`); (2) openrig.dev and github.com/mvschwarz/openrig; (3) optional derived KBs (NotebookLM, generated); (4) this skill's `references/`; (5) memory. A lower rung never overrules a higher one. A command that `--help` does not show is reported as "not found". **Version gate:** this skill was verified on 0.5.14. When `rig --version` differs, say so, treat every command list in `references/` as unverified, re-check each command with `--help` before using it, and stamp answers with the version actually checked. 0.5.14 behavior is never presented as timeless. Rung detail: [`references/sources.md`](./references/sources.md). | OpenRig ships almost daily (twelve releases between 2026-08-26 and 2026-09-14). Only the installed CLI is always version-matched. In this skill's own research, both LLM-derived notes got `rig seat clear-attention` wrong. | OpenRig stops shipping `--help` and `rig context` as its versioned surface. |
| C2 | **Route, never vendor.** First-party skills and docs are loaded live (`rig context get`). `references/` holds only the layer first-party lacks: tiers, trust gates, the external-crew recipe, sandboxed seats, sources. | About 78% of the needed knowledge ships first-party. A copy drifts on the next release. OpenRig is Apache-2.0, and distilled text cites its source. | Never. If a frozen snapshot is required, pin a version explicitly. |
| C3 | **Mutation tiers T0–T3**, each naming the asset it protects ([`references/tiers.md`](./references/tiers.md)). T0 runs freely. T1 needs a delegation naming the rig. T2 also needs a snapshot or rollback first. T3 needs a recorded rationale with its evidence and the least-privilege option (passed as `--reason` only where the installed `--help` exposes that flag; otherwise recorded in the handoff); irreversible T3 actions go to the operator. | Blast radius grows with each tier. OpenRig itself rejects boundaries that cannot name what they protect. | The operator's standing delegation widens a tier explicitly. |
| C4 | **OpenRig records posture; the harness enforces it.** `rig policy` records intent into the RigSpec. Claude Code and Codex permission config is the enforcement surface. Never claim OpenRig blocks an action. | `rig policy --help`: "OpenRig records posture into RigSpec; harness-native permissions enforce — never runtime enforcement." | OpenRig ships runtime enforcement. |
| C5 | **Startup gates are security decisions.** Diagnose with `rig capture`, choose the least-privilege option, and prefer reviewed, durable pre-configuration ([`references/trust-gates.md`](./references/trust-gates.md)). Operator guardrails: **(1)** Codex hooks are trusted only through Codex's native *Review hooks* flow, after reading every definition and script; `trusted_hash` is never written, synthesized or compared by hand; if a hook is unclear, *Continue without trusting*, switch the seat to `claude-code`, or park it. **(2)** Unattended seats encode gated operations as harness `deny` rules, not `ask` prompts. **(3)** Secret values never enter a seat: no secret-manager CLI, secret store, `rig send`, queue item, prompt, culture or startup file, or seat-readable env/config. The project's just-in-time procedure performs the authenticated operation outside the seat and returns only non-secret results. Claude workspace trust is T3 and is reviewed before launch, because OpenRig 0.5.14 auto-accepts it. **(4)** Nothing is trusted because of its name, path or owner alone. **(5)** Attention is diagnostic state. `rig seat clear-attention` (with or without `--reason`) runs only after the cause is resolved and verified with evidence, never to make a rig look green. | Trusting hooks or MCP servers changes what runs outside the sandbox. The hook-trust hashing is undocumented and has already changed under OpenRig (mvschwarz/openrig#17, observed on 0.5.14 + Codex 0.155/0.156). An `ask` prompt freezes a headless pane. | Never. |
| C6 | **Crew isolation.** Each seat's `cwd` is an empty per-seat desk outside every git repository, never a repo worktree: OpenRig 0.5.14 writes a managed block into `<cwd>/CLAUDE.md` at every launch. The seat reaches only its own worktree parent through the harness's additional-directories permission, never the shared parent of all worktrees. Each writing seat works in its own git worktrees under that parent, created under the target project's worktree policy (MAOS default: [`worktree-policy`](../worktree-policy/SKILL.md)); two writers never share one. Never use `rig up --cwd` for a crew: it overrides every member. The project's root checkout stays on its default branch. The reviewer sits in a different pod and, where possible, on a different runtime. Reviewer read-only is not enforced at the shell boundary (Edit/Write denies do not bind Bash) and is unverified; review integrity is bound instead to the exact commit SHA the verdict cites, and only that SHA is pushed or merged (any other SHA needs a new review). Without that SHA binding, do not launch. See [`references/external-crew.md`](./references/external-crew.md) step 5. | A shared root tree breaks every other agent, IDE and human using it. The cwd controls trust, guidance and permissions, and a cwd inside the repo turns launch itself into an edit of a tracked file. Independent review is where model diversity pays off. | Single-seat, read-only rigs; or OpenRig stops writing into `<cwd>` guidance files. |
| C7 | **The queue is the work ledger.** Hand off with `rig queue handoff --body <text>`, with the evidence reference written **inside the body**, and treat the handoff as durable only after `rig queue show <id>` shows that body, reference included. Chat, `rig send` nudges and transcripts are not durable. | Queue handoffs survive restarts, compaction and seat replacement. On 0.5.14 a handoff without `--body` produced an empty body, and `--evidence-ref` was not kept, so only the body is an auditable record. | Never. A release that persists `--evidence-ref` (verified with `rig queue show`) may carry the reference there as well. |
| C8 | **Ownership boundary.** Rigs you did not create (for example an operator's `kernel` rig) get T0 freely. T1+ needs a delegation that names that rig. | Seats in another person's rig carry that person's work and context. | An operator delegation names the rig. |
| C9 | **Project governance outranks the crew.** A crew executes under the target project's own AGENTS.md, runbooks, human gates and secret procedure, carried by the culture file. The crew design adds orchestration and never adds authority. Findings leave only through the project's own channels. | Delegation is bounded by the target project's sovereignty. | Never. |
| C10 | **Verify each mutation through its own T0 read surface, never with an exit code.** Sessions and topology: `rig ps --nodes --rig <rig>`, `rig capture`. Queue: `rig queue show <id>`. Library: `rig specs show <name> --kind <k>`. Config: `rig config get <key>`. Archive: `rig ps --include-archived`. See `references/tiers.md` rule 1. | `rig send` can report success while the text sits undelivered (mvschwarz/openrig#14), and startup state is checked only once and goes stale (#7). Both were open as of 0.5.14; the rule stays even after they are fixed, because a read is cheaper than a wrong assumption. | OpenRig makes its mutation results authoritative end to end. |
| C11 | **Outside-seat scoping is explicit.** With `OPENRIG_SESSION_NAME` unset, pass `--rig <rig>`, `-A` or full session names. Verbs that default to "my rig" return empty, which proves nothing. | Observed on 0.5.14: `rig queue list` prints `[]` outside a seat, and `rig heartbeat` needs a shared-docs root. | OpenRig adds an operator identity for outside sessions. |
