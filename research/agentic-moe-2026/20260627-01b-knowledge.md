## Análise Cross-Group

### 1. Graphify vs. Understand-Anything: Query-Efficiency vs. Exploration/Teaching

Os dois experts de L4 têm filosofias fundamentalmente distintas:

| Dimensão | graphify | Understand-Anything |
|----------|----------|---------------------|
| **Objetivo primário** | Eficiência de tokens em query (~71.5x redução) | Compreensão interativa e onboarding |
| **Metáfora** | "Graph-first retrieval" | "Graphs that teach" |
| **Output central** | Grafo queryable via MCP tools | Dashboard visual interativo |
| **Persona** | Agente autônomo que precisa de contexto barato | Desenvolvedor humano explorando codebase nova |
| **Tech diferencial** | Leiden clustering sem vector DB; SHA256 cache incremental | Multi-agent pipeline (8+ agents especializados); dashboard React com Zustand |
| **Integração MCP** | Sim (nativo, documentado) | Não documentado |
| **Export para L5** | Sim — Obsidian Vault + JSON Canvas | Não |
| **Custo de build** | Alto (Pass 3 para PDFs/imagens/vídeos via LLM) | Moderado (pipeline multi-agente, sem processamento de vídeo/áudio) |
| **Stars (2026-06-27)** | ~52-69k★ (RUN 0: 52,657★) | ~55-66k★ (RUN 0 range) |
| **Linguagens** | 23 (tree-sitter + multimodal) | Multi-linguagem via tree-sitter (sem multimodal declarado) |

**Conclusão chave:** Graphify e Understand-Anything são **complementares, não competidores diretos**. Graphify é a escolha para agentes que precisam de contexto eficiente em tokens durante sessões de desenvolvimento contínuo; Understand-Anything é a escolha para a fase de *onboarding* e *exploração* humana. Em um pipeline MoE maduro, Understand-Anything executa primeiro (gera compreensão), e Graphify serve de context provider durante o trabalho.

**Incompatibilidade a notar:** Graphify tem MCP server nativo enquanto Understand-Anything não — isso favorece Graphify em pipelines de agente autônomo puro. Understand-Anything tem dashboard visual rico que Graphify não oferece como feature nativa.

### 2. Como L4 alimenta L5 (PKM) e L8 (graphiti)

**L4 → L5 (graphify → obsidian-skills):**
A conexão mais concreta é o **export Obsidian Vault** do Graphify (seção 3.2 no DeepWiki). O grafo de codebase torna-se um vault navegável, onde cada nó vira uma nota `.md` e as arestas viram `[[wikilinks]]`. Com obsidian-skills instalado, o agente pode então navegar, editar e enriquecer esse vault com novas notas — criando um loop bidirecional L4↔L5. Esta é a ponte mais acionável do grupo.

Understand-Anything não tem export direto para Obsidian, mas `/understand-knowledge [path/to/wiki]` pode consumir knowledge bases no padrão Karpathy-wiki, que frequentemente são vaults Obsidian — fluxo inverso (L5 → L4).

**L4 → L8 (graphiti — menção como adjacente):**
Graphiti (getzep/graphiti) é um knowledge graph *temporal* focado em episódios de conversação e memória de agente. Graphify e Understand-Anything são knowledge graphs *estruturais* de código. A composição natural: graphify extrai a estrutura estática do codebase → graphiti adiciona a camada temporal (o que mudou, quando, por qual agente, em qual conversa). Graphiti bridging L4↔L8 significa que agentes podem perguntar tanto "qual é a arquitetura atual" (L4) quanto "o que foi feito nessa parte do código na última semana" (L8).

### 3. Overlaps e Colaborações

- **Overlap Graphify–Understand-Anything:** Ambos usam tree-sitter para extração AST, ambos produzem JSON knowledge graphs, ambos suportam Claude Code e Cursor. Sem conflito técnico — podem coexistir no mesmo repo.
- **Colaboração Graphify–obsidian-skills:** Export Obsidian Vault (Graphify) + obsidian-skills (agente sabe escrever/editar vault) = pipeline completo de code→PKM.
- **Sinergia Understand-Anything–obsidian-skills:** `/understand-knowledge` pode ingerir vault Obsidian como knowledge base; obsidian-skills pode criar notas estruturadas com outputs do understand.
